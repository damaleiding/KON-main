# 文风校验与规避词表规则

## 目标

文风校验用于确认文本是否符合目标作品的叙述声音、节奏、词汇习惯和禁用表达。规避词表用于记录不希望在作品中出现、需要谨慎使用或需要替换的词语与表达。

跨项目规则只定义治理方法；具体词表必须放到项目或作品内，避免所有作品共享同一套禁用词。

## 风格事实源

优先级从高到低：

1. 用户当轮明确要求。
2. 目标作品 `设定/风格指南.md`、`故事圣经.md`、`当前状态.md`。
3. 项目 `docs/rules/` 下的作品级或合集级风格规则。
4. 工作区级 `docs/agent-rules/novel-writing.md`。

如果这些来源冲突，先标记冲突，不擅自把某个作品的风格硬套到另一个作品。

## 规避词表字段

建议每个作品维护独立词表，可用 Markdown 表格或 JSON。最小字段：

| 字段 | 含义 |
| --- | --- |
| `term` | 词语、短语、句式或比喻 |
| `category` | banned / caution / replace / allowed |
| `scope` | 全作品、某角色、某视角、某版本、发布稿等 |
| `reason` | 为什么禁用或谨慎 |
| `suggestion` | 替代表达或处理方式 |
| `source` | 用户要求、审稿结论、作品风格指南、历史问题 |
| `updated` | 更新日期 |

## 校验方法

- 规避词命中必须用确定性搜索优先验证，例如 `rg -n -F "词语" <目标路径>`。
- 同形不同义、角色台词刻意使用、引用旧文本等情况应人工判断，不做机械替换。
- 对长句式、语气、节奏和比喻倾向，用审稿判断补充；不得只靠词表判定文风。
- 校验结果应列出文件、位置、命中词、上下文短引、处理建议和是否需要用户确认。

## 文风检查维度

- 叙述视角：人称、距离、信息披露方式是否稳定。
- 节奏：句长、段落长度、动作/心理/对白比例是否贴合目标作品。
- 词汇：是否出现作品禁用词、现代网感词、过度抽象词或不合角色身份的表达。
- 修辞：是否出现过密比喻、机械排比、总结升华、概念化旁白。
- 设定呈现：是否把设定写成解释说明，而不是场景后果。
- 角色声音：对白是否符合人物卡，是否出现互相替换也成立的空泛台词。

## 人写感与反灌水校验

- 扩写后的新增内容应优先检查“事件含量”：是否出现新的动作、反应、阻碍、选择、信息或后果。
- 如果删除形容词、名词意象和抽象心理词后，段落只剩静态氛围，该段应重写为动作链或删减。
- 谨慎使用万能情绪标签、宏大概念、空泛比喻和总结式旁白；需要保留时，必须能说明它服务视角、节奏或人物声音。
- 对白不能只承担解释设定或复述关系；至少应包含试探、回避、压迫、交易、误解、拒绝、让步或遮掩中的一种功能。
- “写得更像人”不等于增加口语废话；应让人物在具体压力下做出不完全、带成本、会留下后果的反应。
- 具体禁用词、慎用句式和替代表达仍应进入项目或作品自己的规避词表，不在跨项目规则中硬编码一套通用词表。

## 修改规则

- 修文前先区分“必须删除”“谨慎重写”“可保留但需说明”。
- 批量替换前必须备份目标文件，并确认替换不会破坏角色台词、专名和旧版本引用。
- 更新词表时记录来源，不把一次临时偏好直接升级为全项目硬规则。
