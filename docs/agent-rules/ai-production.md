# AI 写作生产规则

## 生成规则

- 生成或改写前必须明确用途：设定整理、章节续写、润色、重写、分支试写、发布整理或临时参考。
- 正式写作或改写必须记录 prompt、模型、时间、输入参考、输出路径、版本、用途和筛选结论。
- 文本生成结果必须有可追踪的生成配方，不只保存裸文件。
- 多版本生成要记录版本差异，例如视角、语气、节奏、情节取舍、角色状态或伏笔处理。
- 参考资料必须标注作品、角色、用途、状态和注意事项。废弃参考不得默认进入 prompt。
- 涉及角色身份、关系、时间线、伏笔和世界观规则时，优先使用项目内已锁定设定。
- 对用户展示结果时，优先给出少量精选片段、文件入口或审稿结论，不在聊天里堆叠大量路径。
- 章节生成、润色、拆分、合并或发布整理后，必须按任务需要检查相邻章节首尾、文风、规避词、设定、角色和伏笔。

## Prompt 规则

- Prompt 是生产记录，不是临时聊天文本。
- 生成、修改、审稿或复用 prompt 时，先按 `prompt-generation.md` 执行；尤其是续写、润色、重写、段落扩写和审稿 prompt。
- 重要 prompt 应保存到 `prompts/` 或对应输出目录旁的 `_prompts/`。
- Prompt 文件应说明目标、模型、参考输入、限制条件、版本差异和预期用途。
- 修改既有 prompt 时，应记录源 prompt 路径、问题症状、修改点、预期改善、回归风险和审稿结论。
- 如果实际提交 prompt 使用英文，也应保留中文审稿版，方便用户检查和复用。
- 不把内部标签、目录名、临时编号直接当作模型可见指令，除非它们对生成有明确意义。

## 审稿记录

正式生产结果应尽量记录：

- 任务目标：设定整理、章节续写、润色、重写、分支试写、发布整理或临时参考。
- 输入参考：原文、设定、角色卡、伏笔表、时间线、风格指南和外部参考资料。
- 生成配方：prompt、模型、参数、版本差异和提交命令。
- 输出路径：优先使用项目相对路径。
- 审稿结论：selected、rejected、needs_review、deprecated 或其他项目约定状态。
- 下一步动作：返工、扩展、入库、合并、发布或归档。
