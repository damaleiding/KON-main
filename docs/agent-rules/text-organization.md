# 文本整理规则

## 目标

文本整理用于管理原文、主干、分支、发布稿、输出、账本、prompt 和参考资料的边界，避免正文版本混乱、临时文件污染事实层和上下文读取过长。

## 目录语义

- `原文/`：导入底稿和参考文本，默认只读。
- `设定/`：角色、人设、世界观、术语、时间线、伏笔、风格和当前状态。
- `主干/`：当前认可的正式正文或主要润色稿。
- `分支/`：实验稿、替代路线、局部增补、重设版本。
- `发布/`：对外上传、Google Docs 同步或发布前整理版本。
- `outputs/`：生成、改写、导出或发布前整理结果。
- `_ledger/`：生产账本、版本流转、prompt 索引和审稿决策。
- `review/`：审稿报告、候选对比和采纳结论。
- `_tmp/`：一次性脚本、临时提示词、临时合并稿和排查中间文件。

## 整理原则

- 不直接覆盖 `原文/`；需要改写时复制到工作稿、分支或输出目录。
- 不把临时脚本、临时 HTML/JSON、一次性提示词和未筛选候选稿散放在根目录、作品根目录、`主干/`、`设定/` 或 `发布/`。
- 正式正文修改前按项目备份流程只备份本次会改动的文件。
- 文件移动前先生成迁移表，列出旧路径、目标路径、用途、引用风险和回滚方式。
- 大型外部资料、缓存、临时输出和无索引候选稿不默认进入 Git。

## 版本记录

- 大段改写、章节合并、发布整理、重要审稿结论和用户明确要求记录的修改应写入 `_ledger/`。
- 轻量规则修正、路径查询和纯规划不强制创建分章节账本。
- 分支进入主干前必须记录来源、采纳范围和被替代内容。
- 发布稿应保留来源说明，避免直接从实验分支生成对外版本。

## 字数统计

- 用户提出字数统计、章节长度、全文长度、稿件长度对比时，必须调用 `tools/word-count/`。
- 默认口径是非空白 Unicode 字符数。
- 每章或每部分正文结尾应只有一行字数统计；正文修改后先移除旧统计，再写入新统计。

## 编码与清理

- 中文 Markdown、HTML、JSON 和脚本源码使用 UTF-8。
- 编码修复、批量替换、拆分、合并和字数统计更新都属于正文风险操作，执行前按项目备份流程处理。
- 发现乱码或批量操作事故时，应补充复盘或规则，避免同类问题重复发生。
