# Prompt 生成与修改运行规则

## 目标

本规则用于把写作目标转成可执行、可审稿、可复用的 prompt，也用于修改既有 prompt。它管理的是“提示词生产过程”，不是正文生成结果本身；正文生成、改写和审稿仍按 `ai-production.md`、`novel-writing.md`、`chapter-governance.md` 和项目工作流执行。

## 触发条件

- 用户要求生成、优化、修改、重写或审稿 prompt。
- 需要把章节续写、润色、重写、段落扩写、分支试写或审稿目标转成模型提交词。
- 生成结果出现“太短”“空泛”“词藻堆叠”“动作不足”“不像人写”等问题，需要从 prompt 层定位。
- 需要建立可复用的角色 prompt、风格 prompt、章节生成 prompt、段落扩写 prompt 或审稿 prompt。

## 输入事实

生成或修改 prompt 前，至少明确：

- 任务类型：续写、润色、重写、段落扩写、分支试写、发布整理或审稿。
- 目标作品、目标章节、输入版本、输出位置和是否进入正式生产。
- 可改范围：事实、视角、结构、段落顺序、子情节、对白、动作、设定是否允许变动。
- 不可改范围：锁定设定、角色关系、时间线、伏笔状态、禁用表达和用户当轮硬约束。
- 目标长度和统计口径；默认口径是非空白 Unicode 字符数。
- 参考输入：原文、相邻章节、人物卡、故事圣经、当前状态、伏笔表、风格指南和规避词表。
- 质量门：首尾衔接、动作链、角色声音、反灌水、设定一致、伏笔同步和输出格式。

## 运行流程

1. 读取最小必要上下文，不把无关设定和废弃参考塞进 prompt。
2. 先写“任务契约”：本次要解决什么问题、允许改变什么、必须保留什么、输出应落到哪里。
3. 生成中文审稿版 prompt；如果实际提交需要英文或其他格式，再生成模型提交版，并保留两者关系。
4. 按“目标、输入、硬约束、生成机制、输出格式、自检清单”组织 prompt，避免只写风格形容词。
5. 修改既有 prompt 时，先记录源 prompt 路径或版本、问题症状、修改原因和可能回归点。
6. 提交生成前做 prompt 干检：是否会诱导编造事实、堆词藻、复述设定、忽略动作链或跳过审稿记录。
7. 重要 prompt 保存到项目 `prompts/` 或对应输出目录旁 `_prompts/`，并在账本或 prompt 索引中记录。

## Prompt 结构

建议使用以下字段：

```text
标题：
适用作品/章节：
任务类型：
源 prompt/版本：
问题症状：
目标：
模型：
参考输入：
可改范围：
不可改范围：
生成机制：
输出格式：
质量门：
自检清单：
版本差异：
预期用途：
记录位置：
```

## 段落扩写 Prompt 专项

段落扩写 prompt 必须显式要求：

- 先识别原片段的叙事功能、前后承接、人物目标、当前压力和不可改事实。
- 扩写靠补动作链、阻碍、互动、选择、误解、物件变化、信息变化和小后果完成。
- 新增子情节必须来自既有目标、冲突、关系、物件、时间压力或伏笔。
- 不用静态景物、抽象心理、形容词串、名词意象串、同义反复或总结旁白凑长度。
- 每个新增段落都能说明“谁做了什么、遇到什么阻碍、改变了什么状态”。
- 输出后给出简短扩写说明：新增了哪些动作节点、子情节来源、是否改变事实、需要同步什么。

## 禁止模式

- 只写“扩写到更多字”“写得细腻”“加强氛围”“更有文学性”，却没有动作链和状态变化要求。
- 让模型用大量环境描写、心理描写、形容词或意象补长度。
- 把项目内部路径、临时编号或账本术语直接暴露给模型，除非它们是必要输入。
- 把未筛选外部资料、废弃设定、密钥、token、cookie 或未脱敏内部链接放进 prompt。
- 修改 prompt 后不记录版本差异，导致后续无法复现为什么生成结果变化。

## 审稿清单

- Prompt 是否明确任务类型、输入版本、输出位置和用途。
- Prompt 是否说明可改与不可改范围。
- Prompt 是否把“更长”拆成动作、阻碍、互动、子情节和后果。
- Prompt 是否包含反灌水约束和风格事实源。
- Prompt 是否要求输出自检或生成说明，方便人工筛选。
- Prompt 是否保存到正确位置，并记录模型、时间、版本差异和筛选结论。
