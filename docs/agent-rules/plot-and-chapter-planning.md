# 剧情与章节规划规则

## 目标

本规则用于正式写作前的剧情规划，尤其是把长篇内容拆成可生成、可审稿、可串联的章节单元。默认以“三章剧情单元”为最小规划包：每三章共同推进一个主线节点，同时让至少一条分线有可追踪变化。

## 默认长度

- 单章默认目标长度为 3000 到 6000 字。
- 本工作区默认统计口径是非空白 Unicode 字符数；如平台或用户要求不同口径，必须在规划中注明。
- 低于 3000 字时，应说明该章是否是过渡章、短章、序章或尾声。
- 高于 6000 字时，应优先评估是否拆成上下篇、场景分段或两个章节。

## 篇章与卷

- 每 10 个章节为一个大篇章。
- 每 5 个大篇章为一卷，即 50 个章节。
- 一卷内核心故事发展方向默认锁定，不得在未确认的情况下改变。
- 改变卷核心方向前，应按 `story-canvas.md` 创建方向变更提案。

## 三章剧情单元

每个三章单元应至少包含：

- 单元目标：这三章要让剧情状态发生什么不可逆变化。
- 主线推进：每章分别推进哪一个主线动作、冲突或揭示。
- 分线推进：角色关系、秘密、伏笔、支线任务、对照人物或场景线至少有一条持续变化。
- 情绪阶梯：三章之间的紧张度、暧昧度、危险度、误解或压力不能原地打转。
- 首尾钩子：第 1 章开钩，第 2 章转折或加压，第 3 章阶段性回收并抛出下个单元钩子。

## 章节接力与四账本

- 正式续写前，必须明确上一章继承状态和本章章尾交付物。
- 每章至少更新信息账、资源账、关系账、风险账中的一项；长篇关键章节应多项更新。
- 成功也要留下代价，失败也要产生新知识、排除路径或暴露边界。
- 双线或多线叙事必须做信息交接：发送信息、接收信息、验证动作和回传后果。

## 章内场景颗粒度

- 正式写作前，单章不只规划“发生什么”，还应拆出若干章内场景或段落节点。
- 每个章内场景至少写清：起点状态、人物即时目标、阻碍或干扰、动作链、信息变化、小结果和下一压力。
- 动作链应包含可见行为和互动顺序，例如靠近、试探、被打断、改口、交换物件、移动位置、发现痕迹、做出选择。
- 如果某段预计需要扩写，必须先规划可补的过程节点或子情节来源，不得只写“增加描写”“加强氛围”“写得细腻”。
- 子情节应服务主线压力、人物关系、伏笔、误会、资源损耗或时间限制；不能只是独立小插曲。
- 规划完成后，检查每个长段是否都有状态变化；没有状态变化的段落应缩短、合并或改为可推动后果的动作。

## 主线与分线

- 主线必须回答“读者为什么继续看下一章”。
- 分线必须回答“除了主线事件，人物关系、秘密、状态或世界理解有什么变化”。
- 分线不能长期只做气氛装饰；连续三章没有推进时，应合并、暂停或改写成主线助推器。
- 伏笔属于可追踪分线，必须记录埋设、强化、误导、回收或暂缓状态。

## 规划流程

1. 读取目标作品轻量入口、当前状态、故事圣经、风格指南、伏笔表和必要人物卡。
2. 确定三章单元的起点状态、终点状态和不可逆变化。
3. 为每章分配 3000 到 6000 字目标、章节功能、主线动作和分线动作。
4. 确认三章单元所属篇章和卷，并检查是否偏离卷核心方向。
5. 检查三章之间的首尾承接、冲突升级和信息释放顺序。
6. 输出章节规划表；未进入正式写作前，不改正文。
7. 进入写作后，按 `novel-writing.md`、`chapter-governance.md` 和项目专项工作流执行。

## 检查清单

- 三章是否共同服务一个明确单元目标。
- 每章是否都有独立叙事功能，不只是上一章的延长。
- 主线是否每章推进。
- 分线是否至少一条持续变化。
- 章首是否能接住上一章尾部。
- 章尾是否留下下一章可写、可执行、可验证的具体交付物。
- 信息、资源、关系、风险是否至少一项变化。
- 字数目标是否在 3000 到 6000 字范围内。
- 新增设定、人物变化和伏笔是否进入待同步清单。
