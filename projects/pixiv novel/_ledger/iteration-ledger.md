# 项目迭代账本

## 用途

记录用户每次要求修改、检查后采纳的建议、实际改动方向、设定影响和故事理解沉淀。它是项目逐步形成“我们想创造什么故事”的事实层，不依赖聊天历史。

本文件是总索引，不直接承载所有细节。具体记录按作品、版本/分支和章节拆成独立账本文件。

## 分章节账本位置

分章节账本统一放在：

```text
_ledger/iterations/<作品名>/<版本或分支名>/
```

示例：

```text
_ledger/iterations/曲影番外二/主干拆章原文/
```

## 分章节账本命名

账本文件名必须包含：

- 作品名。
- 版本或分支名。
- 章节编号或章节名。
- 修改日期。
- 操作类型。

推荐格式：

```text
YYYYMMDD_<作品名>_<版本或分支名>_<章节编号或章节名>_<操作类型>.md
```

示例：

```text
20260531_曲影番外二_主干拆章原文_01第一章完美的假面一_自检建议.md
20260531_曲影番外二_主干拆章原文_01第一章完美的假面一_按建议修改.md
```

文件名应避免空格、斜杠、冒号、引号、问号等不稳定字符；章节名过长时可保留章节编号和短标题。

## 记录原则

- 自检只给建议时，也可以创建对应章节的“自检建议”账本，但不标记为已修改。
- 用户明确要求修改后，必须创建或更新对应章节的“按建议修改”账本，记录本次修改对象、用户要求、采纳建议、实际改动、备份位置、复查结论。
- 如果修改影响人物卡、当前状态、伏笔表、分支记录或故事圣经，必须在记录中列出待同步或已同步项。
- 记录要客观，不把未确认的推测写成事实；新设定先标记为“待确认”。
- 总索引只登记分章节账本路径、操作日期、作品、版本、章节和一句话结论。

## 记录模板

```text
## YYYY-MM-DD｜作品｜章节或文件｜操作类型

- 用户要求：
- 检查依据：
- 自检结论：
- 采纳建议：
- 实际改动：
- 备份位置：
- 复查结论：
- 设定影响：
- 人物卡同步：
- 伏笔/状态同步：
- 故事理解沉淀：
- 下一步：
```
