# 章节衔接与章节确定规则

## 项目级硬规则

- 单章默认目标长度为 3000 到 6000 字；三章剧情规划读取 `chapter-planning.md`。
- 章节生成、润色、拆分、合并和发布整理后，必须检查相邻章节首尾。
- 上一章尾部应留下具体承接点，不默认用总结升华收束。
- 下一章开头应接住上一章尾部，不复述上一章已经完成的动作。
- 下一章必须继承上一章至少一个具体状态：信息、物件、伤害、位置、风险、承诺、误会、情绪后果或资源变化。
- 章尾交付物必须能转化为下一章开场动作；纯抽象悬念不算合格交付。
- 拆章或合并必须留下来源、范围、被替代内容和必要账本记录。
- 已有作品的命名规则优先于新规则；新作品优先使用稳定数字前缀。

## 推荐检查路径

1. 读取 `_pipeline/chapter-continuity-workflow.md`。
2. 读取目标章节和必要相邻章节。
3. 读取目标作品 `设定/当前状态.md`、`设定/风格指南.md` 和必要伏笔表。
4. 输出“通过 / 需要修改 / 上下文不足”结论。

## 常见问题

- 章尾突然总结主题。
- 章首重复上一章最后已经完成的动作。
- 跳时、换地、换视角没有锚点。
- 拆分后每段都像中间段，没有独立功能。
- 合并后字数统计、章节标题或发布来源没有同步。
- 四账本没有变化：信息、资源、关系、风险都停在原地。
- 对话只表达情绪或解释设定，没有改变行动、判断或关系。
