# 工具层与生成层边界规则

## 目标

本规则用于把网页端、sidecar、脚本和可视化工具形成的“工具层”，与写作规则、prompt、范文学习和正文生成形成的“生成层”分开管理。两个层可以通过稳定数据契约交接，但不得互相拥有对方的规则、目录或事实。

核心目标：工具改动不误伤生成规则，生成规则更新不误改网页工具和数据结构。

## 层级定义

| 层级 | 负责什么 | 主要空间 |
| --- | --- | --- |
| 工具层 | 网页 UI、交互、画布布局、sidecar、历史快照、脚本、schema、工具 README、启动方式和数据读写边界 | 工作区 `tools/`、项目 `90_工具/`、正文旁 `.story.json`、`.story-canvas.folder.json`、`.story-canvas.ledger.jsonl`、`.story-history/` |
| 生成层 | 小说生成规则、章节规划、prompt 模板、范文学习沉淀、写作自检、审稿标准和模型提交词 | 项目 `docs/rules/`、`prompts/`、`refs/范文参考/analysis/`、`methods/`、`templates/`、生产账本 |
| 桥接层 | 工具层记录给生成层读取的请求、锚点、用户直接意见、候选状态和输出路径 | `generation_requests`、`reroll` 记录、剧情块锚点、设定增量表、账本索引 |

## 工具层硬边界

- 工具层可以记录用户输入、选区锚点、生成请求、候选版本、节点位置、历史快照和同步状态。
- 工具层不保存长篇生成规则全文，不内置 prompt 模板，不决定章节质量门，不自动采纳候选正文。
- 网页文案、按钮、字段、schema 或 sidecar 改动不得顺手修改 `docs/rules/longform-generation.md`、`prompts/` 或 `templates/`，除非任务明确要求同步生成层。
- 工具产生的 `.story.json`、`.story-canvas.folder.json`、`.story-canvas.ledger.jsonl` 和 `.story-history/` 是工具状态与桥接数据，不等同于稳定作品设定。
- 工具层不得直接覆盖 `主干/` 正文、人物卡、伏笔表或发布稿；候选进入正文必须经过生成层或项目工作流确认。

## 生成层硬边界

- 生成层可以读取工具层的请求、锚点、用户直接意见、候选状态和账本记录，并把它们作为输入事实。
- 生成层不修改网页 UI、按钮逻辑、sidecar schema、历史快照机制或工具启动方式，除非任务明确是工具维护。
- 修改 `docs/rules/longform-generation.md`、prompt 模板或范文沉淀时，不自动迁移、重写或删除既有 `.story.json` 和画布账本。
- 生成层输出候选正文时，应写明输入参考、模型、时间、输出路径、版本和筛选结论；不要把候选默认为已采纳事实。
- 生成层如果需要把候选应用到正文，必须按正文备份、字数统计、人物卡同步和账本记录流程执行。

## 桥接契约

工具层给生成层的最小交接字段建议包括：

```text
目标作品/文件夹：
目标章节或剧情块锚点：
任务类型：
用户直接意见：
可改范围：
不可改范围：
目标字数：
候选版本数：
输出偏好：
来源 sidecar / ledger 路径：
```

桥接字段只描述“用户要什么、选中了哪里、希望生成什么候选”，不承载完整生成规则。生成层读取桥接字段后，再按对应项目规则、作品设定和 prompt 模板组织模型提交词。

## 冲突处理

冲突优先级由生成层解释，不由网页工具写死。默认顺序：

1. 用户当轮在聊天中给出的直接意见。
2. 用户在网页工具中保存的直接意见或 reroll 目标。
3. 锁定作品事实、时间线、角色关系和不可改设定。
4. 项目生成规则、章节接力卡、四账本/方案账和 prompt 模板。
5. 默认风格建议和通用偏好。

如果网页意见与生成规则冲突，生成层按用户具体意见执行，并在生成说明中标出冲突。不得通过修改工具文案或工具 schema 来静默改变生成规则。

## 修改检查清单

修改工具层时检查：

1. 是否只改了工具 UI、工具文档、脚本、schema 或 sidecar 读写？
2. 是否避免把生成规则、prompt 长文或文风细则写入工具 README？
3. 是否没有自动改动 `docs/rules/`、`prompts/`、`templates/`？
4. 如果新增桥接字段，是否同步说明字段含义和兼容策略？

修改生成层时检查：

1. 是否只改了写作规则、prompt、范文方法、审稿标准或生成工作流？
2. 是否避免改动 `tools/story-canvas/`、`.story.json` schema 和网页交互？
3. 是否没有把候选正文、网页状态或 sidecar 记录误写成稳定设定？
4. 如果生成层需要新桥接字段，是否先记录需求，再单独安排工具层改动？

## 文件落点

- 工具层规则和实现说明：工具目录 README、工具旁 schema、项目 `_pipeline/tool-index.json`。
- 生成层规则和 prompt：项目 `docs/rules/`、`prompts/`、工作区 `templates/`。
- 桥接层说明：本文件、`story-canvas.md`、`story-canvas-workflow.md` 中的字段说明。
- 生产事实：`_ledger/`、`review/`、输出旁 `_prompts/`，不写进工具实现目录。
