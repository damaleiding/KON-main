# Novel 小说创作工程

这个项目是 KVA 工作区下的小说创作工程，用于统一管理既有作品、设定、正文、分支稿、发布稿、写作 prompt、审稿记录和后续整理流程。

当前整理原则是：先保留既有作品目录和文件路径，补齐标准项目入口；后续再按索引逐步迁移或归档，不直接打散已有正文。

## 标准入口

- `AGENTS.md`：小说项目长期规则。
- `PROJECT.md`：项目记忆，记录作品范围、当前状态和待整理问题。
- `WORKFLOW.md`：小说写作、润色、分支合并和发布整理流程。
- `novel_project-brief.html`：给人类快速阅读的静态项目纲要。
- `_pipeline/`：上下文路由、目录映射、章节自检流程和工具索引。
- `_ledger/`：写作账本、prompt 索引、审稿决策和版本流转记录。
- `docs/`：项目说明、结构整理、复盘和迁移记录。
- `refs/`：跨作品参考资料和外部参考索引。
- `prompts/`：可复用写作、润色、审稿和替换 prompt。
- `outputs/`：生成、改写、整理、导出的临时或阶段性结果。
- `review/`：审稿记录、候选稿对比和分支采纳结论。
- `trash/`：废弃稿、失败尝试和临时材料。

## 既有内容入口

- `人偶番外/`：人偶番外项目，包含主干章节、成人化重设分支、增补分支、设定与发布稿。
- `曲影/`：曲影项目，包含原文、角色设定与润色主干。
- `曲影番外二/`：曲影番外二项目，包含导入原文、拆章主干、设定资料和人物卡。
- `柠檬/`：柠檬项目，包含原始文本、拆章主干与新作分支。
- `00_项目管理/`：项目结构、写作流程、skill 调研和后续规划。
- `90_工具/`：辅助脚本与批处理工具。
- `.trae/skills/`：本项目自定义 Trae skills。

## 使用规则

- `原文/`：只放参考文本和导入原稿，默认不直接改写。
- `设定/`：放角色卡、世界观、术语表、时间线、伏笔表等稳定资料。
- `主干/`：当前认可的正式正文或主要润色稿。
- `分支/`：实验稿、重设稿、平行版本、局部增补。
- `发布/`：上传平台或对外整理的合并版本。
- `归档/`：废弃但需要保留的历史材料。
- `_ledger/`：项目级事实记录，优先记录重要改写、合并、发布和审稿决策。
- `_pipeline/`：项目级上下文路由，说明不同任务应该先读哪些文件。
- 章节自检：生成、润色、改写、合并或用户指定检查章节后，按 `_pipeline/chapter-self-check-workflow.md` 读取设定、当前状态、伏笔、角色卡和风格指南进行复查。
- 修改迭代：自检默认只给建议，并优先生成 HTML 网页报告；用户明确要求修改后，按备份、修改、复查流程执行，把本次修改写入对应分章节账本，`_ledger/iteration-ledger.md` 只作为总索引。
- Google Docs 同步：用户要求同步到 Google 文档时，按 `_pipeline/google-docs-clasp-sync-workflow.md` 使用 `clasp` / Apps Script；本地正文仍是事实层，Google Docs 是发布或协作副本。

## 分支合并原则

- 分支内容进入主干前，先确认不会破坏设定、人设和时间线。
- 每次合并应保留来源说明，例如“来自 成人化重设 第八章中段”。
- 发布稿只从主干或已确认合并的分支生成，不直接从实验分支上传。
