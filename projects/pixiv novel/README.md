# Pixiv Novel 小说创作项目（历史归档）

> 迁移完成提示：本目录已迁出，不再作为默认工作入口。生成层请使用 `projects/story-engine/`，工具层请使用 `projects/story-canvas/`。本目录仅用于历史对照、回滚参照和人工核查。

这个目录是 KVA 工作区下的整体小说创作项目，用于统一管理多部小说作品、通用写作经验、设定资料、正文版本、分支稿、发布稿、提示词、审稿记录、工具流程和后续复用方法。

迁移提示：本项目已拆分迁入 `projects/story-engine/` 和 `projects/story-canvas/`。当前本目录作为历史归档/回滚入口保留；后续新增生成规则、prompt、工具代码和作品维护应进入新项目路径。

当前整理原则是：保留一个统一主项目入口，内部按作品模块管理；通过轻量索引和上下文路由减少每次任务的读取范围，而不是把所有作品拆散成互不关联的项目。

## 标准入口

- `AGENTS.md`：项目级长期规则，强调最小上下文、触发式工作流和经验复用。
- `PROJECT.md`：项目记忆，记录作品范围、当前状态和待整理问题。
- `WORKFLOW.md`：项目整理、写作、润色、分支合并、发布同步和方法沉淀流程。
- `novel_project-brief.html`：给人类快速阅读的静态项目纲要。
- `_pipeline/`：上下文路由、目录映射、章节自检流程和工具索引。
- `docs/rules/`：项目级故事画布、三章规划、长篇生成、章节衔接、文风校验、规避词表、文本整理和工具/生成分层规则。
- `docs/rules/layer-boundaries.md`：网页工具层、sidecar、脚本与生成规则、prompt、范文沉淀之间的边界和桥接契约。
- `docs/rules/path-and-naming.md`：路径结构、文件命名、各区域生成规则和生成后同步清单。
- `_ledger/`：写作账本、prompt 索引、审稿决策和版本流转记录。
- `docs/`：项目说明、结构整理、复盘和方法沉淀记录。
- `refs/`：跨作品参考资料和外部参考索引。
- `prompts/`：可复用写作、润色、审稿和替换 prompt。
- `outputs/`：生成、改写、整理、导出的临时或阶段性结果。
- `_tmp/`：一次性脚本、临时提示词、临时合并稿和排查中间文件；默认不纳入 Git。
- `review/`：审稿记录、候选稿对比和分支采纳结论。
- `trash/`：废弃稿、失败尝试和临时材料。

## 作品模块

- `曲影番外二/`：当前重点生产作品，包含导入原文、拆章主干、设定资料、人物卡、局部账本和 Google Docs 同步稿；其流程经验优先沉淀为项目级方法。
- `人偶番外/`：人偶番外作品，包含主干章节、成人化重设分支、增补分支、设定与发布稿。
- `曲影/`：曲影系列基础材料，包含原文、角色设定与润色主干。
- `柠檬/`：柠檬作品，包含原始文本、拆章主干与新作分支。
- `00_项目管理/`：旧项目管理和结构说明；保留作历史入口，后续可迁移到 `docs/`。
- `90_工具/`：辅助脚本与批处理工具；通过 `_pipeline/tool-index.json` 登记。
- `.trae/skills/`：本项目自定义 Trae skills；不作为默认上下文读取。

## 使用规则

- `pixiv novel` 是统一小说项目；具体正文仍按作品模块放在各自 `主干/`、`分支/`、`发布/` 中。
- 新增文件先按 `docs/rules/path-and-naming.md` 判断落点和命名；既有正文不因规则更新自动重命名。
- `原文/` 只放参考文本和导入原稿，默认不直接改写。
- `设定/` 放角色卡、世界观、术语表、时间线、伏笔表等稳定资料。
- `主干/` 放当前认可的正式正文或主要润色稿。
- `分支/` 放实验稿、重设稿、平行版本、局部增补。
- `发布/` 放上传平台、Google Docs 或对外整理的合并版本。
- `_tmp/` 只放临时文件，禁止把临时脚本或中间稿散放在项目根目录、作品根目录或 `主干/`。
- `_ledger/` 记录重要改写、合并、发布和审稿决策；轻量查询和规则修正不强制写分章节账本。
- `_pipeline/` 说明不同任务应该先读哪些最小文件。

## 分支合并原则

- 分支内容进入主干前，先确认不会破坏设定、人设和时间线。
- 每次合并应保留来源说明，例如“来自 成人化重设 第八章中段”。
- 发布稿只从主干或已确认合并的分支生成，不直接从实验分支上传。

## 下一步整理

1. 为每个既有作品补齐最小索引：作品目标、主干入口、设定入口、分支入口、发布状态和可复用经验。
2. 优先从 `曲影番外二/` 沉淀项目级写作流程、审稿规则、提示词和同步方法。
3. 将 `00_项目管理/项目结构说明.md` 的内容合并或迁移到 `docs/`，保留旧路径说明。
4. 将 `90_工具/` 中可复用脚本登记到 `_pipeline/tool-index.json`。
5. 需要物理移动正文文件前，先生成迁移表，确认旧路径、目标路径、引用影响和回滚方式。

## 文风与衔接补充

- 章节修改和生成时，除检查设定一致性外，还要检查章首是否复述上一章、章尾是否变成总结升华。
- 设定应沉入场景和动作，不直接在正文中解释“这是什么设定”“这个场景的作用是什么”。
- 修改正文后继续按备份、复查、必要账本记录和待同步标记流程执行。
- 规则读取按 `_pipeline/rule-router.md` 进行；故事画布、三章规划、首尾衔接、文风质量、规避词表和文本整理分别维护在 `_pipeline/`、`docs/rules/` 与 `_ledger/story-canvas/` 的专项文件中。
- 网页端、sidecar 和脚本属于工具层；写作规则、prompt 和范文沉淀属于生成层。两层交接和修改边界以 `docs/rules/layer-boundaries.md` 为准。
- 路径结构、命名规范和各区域生成规则以 `docs/rules/path-and-naming.md` 为准；需要物理迁移时先写迁移表。
