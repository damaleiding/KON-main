# Gemini 辅助写作分工流程

## 目的

本流程用于固定 `pixiv novel` 项目中的外部模型辅助写作方式：Trae 负责项目事实层、剧情规划、对白规划和版本回收；Google Gemini 由用户在本地环境中调用，承担外部扩写或改写试验。

本流程不设置单独的内容安全审核节点。回收阶段只做结构、连续性、格式、密钥、路径和版本记录检查。

## 角色分工

| 环节 | 负责方 | 输出 |
| --- | --- | --- |
| 任务拆解 | Trae | 写作目标、输入文件、输出路径、版本用途 |
| 剧情规划 | Trae | 章节功能、冲突设计、情绪曲线、场景顺序 |
| 对白规划 | Trae | 对白目标、角色语气、信息释放、潜台词 |
| 外部扩写 | 用户本地 Gemini | 扩写稿、重写稿或试验稿 |
| 回收整理 | Trae | 连续性检查、结构优化、格式整理、发布准备 |
| 生产记录 | Trae | prompt、模型、时间、输入输出路径和筛选结论 |

## 标准流程

1. 明确任务类型：设定整理、章节续写、润色、重写、分支试写、发布整理或临时参考。
2. 读取最小上下文：先读项目入口，再按 `_pipeline/context-routes.md` 读取目标作品的设定、主干或分支。
3. 生成规划稿：Trae 输出剧情目标、场景节奏、对白骨架、人物动机和需要保留的事实点。
4. 保存规划稿：重要规划或 prompt 放入 `prompts/`，或放入目标输出旁的 `_prompts/`。
5. 本地调用 Gemini：用户在本机使用 `.env` 中的 `GOOGLE_API_KEY` 和 `GOOGLE_GEMINI_MODEL` 调用外部模型。
6. 回收生成稿：用户把需要处理的稿件、摘要或文件路径交回 Trae。
7. 结构整理：Trae 检查剧情连续性、设定一致性、对白功能、章节节奏、命名格式和输出路径。
8. 记录结论：重要版本写入 `_ledger/` 或作品内 `设定/分支记录.md`、`设定/当前状态.md` 等记录文件。

## 文件落盘

| 内容类型 | 推荐位置 | 说明 |
| --- | --- | --- |
| 通用 prompt 模板 | `prompts/` | 可复用模板，避免只留在聊天记录中。 |
| 单次规划稿 | `outputs/` 或目标作品 `_prompts/` | 临时规划可放输出旁，便于追踪。 |
| 分支试验稿 | `<作品>/分支/<方向名>/` | 不直接覆盖 `主干/`。 |
| 发布整理稿 | `<作品>/发布/` | 只从主干或已确认合并的分支生成。 |
| 重要生产记录 | `_ledger/` | 记录模型、时间、输入、输出、版本用途和筛选结论。 |

## Gemini 本地配置

真实 Key 只允许写入仓库根目录 `.env`，不要写入 `.env.example`、正文、prompt、账本、README 或聊天记录。

`.env` 示例：

```env
GOOGLE_API_KEY=你的真实GoogleAIStudioKey
GOOGLE_GEMINI_MODEL=gemini-3.5-flash
```

`.env.example` 只保留占位符：

```env
GOOGLE_API_KEY=<your-google-ai-studio-api-key>
GOOGLE_GEMINI_MODEL=gemini-3.5-flash
```

## 回收检查清单

- 是否保留既有设定、角色关系和时间线。
- 是否明确区分 `主干/`、`分支/`、`发布/` 和 `outputs/`。
- 是否记录输入文件、输出文件、模型、时间和版本用途。
- 是否避免把真实 Key、内部链接或本地路径泄露到可提交文本中。
- 是否需要更新 `设定/分支记录.md`、`设定/当前状态.md` 或 `_ledger/`。

## 默认约定

- 未明确指定时，所有操作默认限制在 `projects/pixiv novel/` 项目内。
- `原文/` 默认只读，改写应进入 `分支/`、`outputs/` 或用户指定路径。
- Gemini 生成稿不自动进入主干；进入主干前必须有来源、采纳范围和替代内容记录。
- Trae 最终交付以文件系统中的事实层为准，不以聊天历史作为唯一依据。
