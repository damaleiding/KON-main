# 章节首尾衔接工作流

## 触发场景

- 用户要求检查“上一章和下一章是否串联”。
- 章节续写、润色、拆分、合并、重命名或发布整理之后。
- 发现章尾有总结升华、章首复述上一章动作、跳时换地不清楚等问题。

## 必读上下文

1. 目标章节。
2. 上一章节尾部，至少最后 800 到 1500 个非空白字符，视章节节奏调整。
3. 下一章节开头，至少开头 800 到 1500 个非空白字符；如果是续写新章，则读取最近主干章节尾部。
4. 目标作品 `设定/当前状态.md`、`设定/风格指南.md` 和必要伏笔表。

## 检查项

- 上一章尾部是否留下可承接的动作、物件、声音、情绪、问题或现场状态。
- 下一章开头是否接住这个承接点，而不是重复上一章已经完成的动作。
- 下一章是否继承上一章至少一个具体状态：信息、物件、伤害、位置、风险、承诺、误会、情绪后果或资源变化。
- 章尾交付物是否能转化为下一章开场动作。
- 是否存在无说明跳时、换地、换视角。
- 章尾是否用总结、宣告、升华或抽象旁白替代具体收束。
- 章首是否用大段设定解释代替现场推进。
- 四账本是否至少一项变化：信息、资源、关系、风险。
- 主要对话是否推动行动、判断或关系变化。
- 新埋或回收的伏笔是否需要同步到伏笔表或待办。

## 输出格式

```text
结论：通过 / 需要修改 / 上下文不足
检查范围：
- 上一章：
- 目标章：
- 下一章：

问题清单：
- 位置：
- 问题：
- 依据：
- 建议：

待同步：
- 伏笔表：
- 当前状态：
- 四账本：
- 章节索引：
```

## 修改规则

- 默认只给建议，不直接改正文。
- 用户要求修改时，先执行 `_pipeline/text-version-backup-workflow.md`。
- 修改后重新检查首尾，并更新字数统计和必要账本。
