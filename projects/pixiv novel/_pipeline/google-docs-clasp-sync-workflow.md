# Google Docs clasp 同步工作流

## 适用场景

- 用户要求把主干、发布稿、润色稿或合并稿同步到 Google Docs。
- 用户要求后续修改继续上传到同一个 Google 文档。
- 用户指定用 `clasp`、Google Apps Script 或 Google Docs 作为发布/协作目标。

## 基本原则

- 文件系统仍是事实层；Google Docs 是同步目标，不反向作为唯一事实层。
- 同步前确认来源目录或文件、目标 Google 文档、新建/覆盖/追加策略和排版要求。
- 默认从 `主干/` 或已确认的 `发布/` 版本同步，不直接上传实验分支。
- 已绑定 Google Docs 的版本，在每次本地正文修改、字数统计和账本记录完成后，默认覆盖同步到同一文档；用户明确要求暂不同步时才跳过。
- 同步排版尽量贴近本地 Markdown，同时为审阅友好采用较松的段落间距；标题、章节分隔线、段落顺序、字数统计和引用说明必须保留。
- 每次同步后记录来源路径、目标文档标识、同步时间、同步方式和结果。
- 不把 Google OAuth token、cookie、真实 API Key 或未脱敏凭据写入项目文件。

## 环境要求

- 本机可运行 Node.js、npm 和 `clasp`。
- 已执行 `clasp login`，并在 Google 账号中开启 Apps Script API。
- Google Apps Script 项目已授权访问目标 Google Docs。
- 需要真实文档 ID 时，优先由用户提供；如需记录，写入本地未同步配置或脱敏账本。

## 推荐流程

1. 读取项目规则：`AGENTS.md`、`PROJECT.md`、`WORKFLOW.md` 和本文件。
2. 确认同步来源：单个章节、整部作品目录、发布稿或临时合并稿。
3. 检查 `node --version`、`npm --version`、`clasp --version`。
4. 如本机缺少环境，先向用户说明缺口，不伪造已上传结果。
5. 准备 Google Apps Script：使用 `DocumentApp` 创建或打开文档，按标题、段落和分隔线写入正文。
6. 使用 `clasp push` 部署脚本，再用 `clasp run` 执行同步函数。
7. 如果 `clasp run` 被 API executable 限制拦截，可使用 `90_工具/google-docs-sync/upload-markdown-to-drive-doc.js` 通过 Drive API 上传并转换为 Google Docs。
8. 对小说正文默认使用“loose”排版：保留本地段落，同时将过长段落按中文标点温和拆分，方便逐段查看和批注。
9. 同步完成后读取命令结果，向用户报告文档链接或文档 ID、同步范围和失败项。
10. 写入 `_ledger/`：记录来源、目标、时间、同步状态、排版策略和后续增量更新规则。

## 后续改动同步

- 如果正文发生修改，先完成正文备份、修改、字数统计和账本记录。
- 再重新生成 `发布/GoogleDocs/` 下的同步稿，并按本工作流把已确认的新版本覆盖同步到同一 Google 文档。
- 若只修改部分章节，可优先增量更新对应章节；无法稳定定位章节时，覆盖重建整篇文档正文。
- Google 文档中的手动修改不自动回写本地，除非用户明确要求导入并做冲突处理。

## 排版策略

- `preserve`：严格按本地 Markdown 的空行和段落转换，不额外拆段。
- `loose`：默认策略；保留本地 Markdown 结构，并对超长自然段按 `。！？；……` 等标点做温和拆分。
- 标题行 `#` 到 `######` 转成 Google Docs 标题层级；`---` 转成分隔线；引用统计行保留为独立段落。
- 不为了排版改写正文词句，不删除字数统计，不改变章节顺序。

## 记录字段

每次同步建议记录：

- 作品名、版本名、来源路径。
- Google 文档标题、文档 ID 或脱敏链接。
- 同步模式：新建、覆盖、追加、增量章节更新。
- 排版策略：`preserve`、`loose` 或其他用户指定策略。
- 工具：`clasp`、Apps Script 函数名、执行账号。
- 结果：成功、部分失败、失败原因、待用户处理事项。
