# Novel 项目规则

## 项目定位

`projects/novel` 是 KVA 的小说创作工程，用于管理既有作品、设定资料、正文主干、分支稿、发布稿、写作 prompt、审稿记录和版本流转。

## 最高原则

- 文件系统是事实层，聊天历史不是事实层。
- `原文/` 默认只读，不直接覆盖；需要改写时先复制到 `分支/`、`outputs/` 或指定工作稿。
- 修改正文前必须按 `_pipeline/text-version-backup-workflow.md` 备份本次会改动的文件；拆分、合并、格式清理、编码修复、字数统计更新都算正文修改。
- `设定/` 是连续性依据，涉及角色、人设、时间线、伏笔和世界观时优先读取。
- 人物卡跟随正文走；章节、分支或发布稿中出现的角色，必须读取对应人物卡，并在剧情新增或改动后同步更新人物卡。
- 章节生成、续写、润色、改写、合并、发布整理完成后，或用户要求检查章节时，必须按 `_pipeline/chapter-self-check-workflow.md` 做自检。
- `主干/` 是当前认可版本；`分支/` 是实验方向；`发布/` 只从主干或已确认合并的分支生成。
- 大段改写、章节合并、发布整理和重要审稿结论应写入 `_ledger/` 或对应作品的记录文件。
- 同步到 Google Docs 时，优先按 `_pipeline/google-docs-clasp-sync-workflow.md` 使用 `clasp` / Google Apps Script；本地正文仍是事实层，Google Docs 是发布或协作副本。
- 自检和检查默认只给修改建议，不直接修改正文；用户明确要求修改后，才进入备份、修改、复查流程。
- 用户每次要求修改正文或设定后，必须写入对应分章节账本，并在 `_ledger/iteration-ledger.md` 总索引登记路径和一句话结论。
- 对已绑定 Google Docs 的版本，每次正文修改完成并记录后，必须自动标记为“待同步”；只有在本轮修改结束或用户明确发出“上传/同步/发布”指令时，才覆盖同步到同一 Google 文档。
- 物理移动既有正文前，先生成迁移表并确认旧路径、目标路径和引用影响。

## 读取顺序

1. 先读本文件、`PROJECT.md` 和 `WORKFLOW.md`。
2. 再读 `_pipeline/context-routes.md`，确认任务需要的最小上下文。
3. 如果任务属于某个作品，优先读该作品的 `设定/`、`主干/` 和必要的 `分支/`。
4. 如果任务涉及正文写作、润色、改写、分支试写或发布整理，必须按 `_pipeline/character-card-workflow.md` 读取出场人物的人物卡。
5. 如果任务会覆盖、拆分、合并、清理格式、修复编码或更新字数统计，必须先读 `_pipeline/text-version-backup-workflow.md` 并建立备份。
6. 如果任务涉及发布或合并，必须读取对应作品的 `发布/`、`分支记录.md`、`当前状态.md` 或同类记录。
7. 如果任务涉及生成后自检或用户指定检查章节，必须读取 `_pipeline/chapter-self-check-workflow.md`，并按作品读取 `故事圣经.md`、`风格指南.md`、`当前状态.md`、`伏笔表.md`、`角色卡.md` 和出场角色人物卡。
8. 如果任务涉及 Google Docs 同步、`clasp` 部署或 Apps Script 上传，必须读取 `_pipeline/google-docs-clasp-sync-workflow.md`。

## 写作约束

- 不编造未在设定或原文中出现的关键事实；需要新增设定时标记为“待确认”。
- 润色应尽量保留原章节事实、人物关系和叙事功能，除非任务明确要求重写。
- 每一部分/每一章正文结尾必须且只能带有一个字数统计（如 `> 本章字数统计：XXXX 字（非空白字符）`）。若内容有修改，必须先移除旧统计，再同步更新为唯一的新统计。
- 分支稿进入主干前，应记录来源、采纳范围和被替代内容。
- 发布稿应保留来源说明，避免直接从实验分支生成对外版本。
- 新增或改变角色经历、状态、关系、心理、秘密、伏笔或限制时，应同步写入或建议写入对应独立人物卡。
- 自检默认先报告问题和修改建议，不直接改正文；需要修正文稿时，先备份目标文件，再修改并复查。
- 修改完成后必须更新分章节账本和 `_ledger/iteration-ledger.md` 总索引，让项目逐步沉淀用户偏好、故事方向和长期修订经验。
- Google Docs 状态变更必须记录来源路径、目标文档、同步模式、精确到秒的时间和结果；实际上传记录上传时间，待同步记录本地变更时间；不得把 OAuth token、cookie、API Key 或未脱敏凭据写入项目文件。
- Google Docs 排版应尽量贴近本地 Markdown：保留标题层级、章节分隔线、段落顺序和字数统计；为方便审阅，可在不改变正文语义的前提下采用更松的段落间距，并对过长段落做温和断句分段。
