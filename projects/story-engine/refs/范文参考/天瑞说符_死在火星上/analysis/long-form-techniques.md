# 长篇专项学习：硬约束生存与资源账本

## 学习定位

本篇最值得迁移的是“硬条件连续性”。剧情不是靠随机灾难堆叠，而是由资源、工程、时间窗口和失败代价逐步收紧。读者愿意跟长篇走下去，是因为每个解决方案都会留下新的限制。

## 核心结构

1. 危机先变成可计算问题。
   生存压力如果只写成情绪，会很快重复；把它拆成氧气、食物、能源、轨道、通信、维修、天气等具体变量，剧情就有了可追踪的推进面。

2. 每次解决都要付出资源。
   方案成功不代表压力消失，而是资源账本变化：时间减少、备用件损耗、救援窗口变窄、人物体力或心理承压。这样成功也能继续制造故事。

3. 失败不是归零，而是产生知识。
   工程试错的魅力在于：失败会暴露新边界、修正旧判断、排除一条路径。只要失败留下信息，章节就不是白走。

4. 幽默和日常感是节奏阀。
   孤绝生存题材很容易长期高压。轻微幽默、吐槽、日常动作和技术细节能让读者喘气，同时强化人物“不被环境吞没”的生命感。

## 上下文连续方法

每一段推进都应保留一个“账本变化”：

1. 资源账本：什么变少了，什么还能用？
2. 风险账本：什么新风险被发现？
3. 方案账本：哪个方案被证明可行、不可行或部分可行？
4. 关系账本：角色之间的信任、依赖、分歧是否变化？

长篇中段尤其要避免“危机解决后状态复原”。更稳的做法是：危机被解决，但世界条件更窄，下一次选择更少。

## 可迁移章节模板

| 环节 | 写作问题 | 输出物 |
| --- | --- | --- |
| 硬约束 | 本章最硬的限制是什么？ | 数量、时间、空间、规则或损坏状态 |
| 拆解 | 角色把限制拆成哪些子问题？ | 任务清单 |
| 试错 | 哪个方案被尝试？ | 行动过程 |
| 代价 | 成功或失败消耗了什么？ | 资源变化 |
| 新知 | 角色知道了什么新的边界？ | 修正后的判断 |
| 钩子 | 下一章继承哪个限制？ | 更窄的选择或新的救援窗口 |

## KVA 使用规则

- 生存类章节结尾必须更新资源、风险、方案三张账。
- 技术细节要服务选择，不要成为资料展示；一项参数最好对应一个动作后果。
- 救援线不能过早变宽，最好让希望出现的同时附带更苛刻条件。
- 对话要承担协作、分工、计算确认或情绪缓冲功能，不能只解释设定。
- 失败章节要写“学到了什么”，否则会像原地打转。

## 学习结论

本篇可以作为 KVA 的“硬科幻生存长篇”范式：用资源账本保证连续性，用工程拆解推动章节，用失败知识制造推进，用幽默和日常动作降低阅读疲劳。
