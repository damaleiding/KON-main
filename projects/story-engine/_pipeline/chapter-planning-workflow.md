# 三章剧情单元规划工作流

## 触发场景

- 用户要求规划三章、几章、下一阶段剧情、主线和分线。
- 正式续写前，需要先确定章节长度、章节功能和剧情推进。
- 现有章节发生拆分、合并或节奏失衡，需要重新规划单元结构。

## 默认目标

- 单章默认 3000 到 6000 字。
- 默认口径为非空白 Unicode 字符数。
- 三章作为一个剧情单元：第 1 章开钩，第 2 章加压或转折，第 3 章阶段回收并抛出下一单元钩子。

## 必读上下文

1. 项目 `AGENTS.md`、`PROJECT.md`、`WORKFLOW.md`。
2. `_pipeline/context-routes.md`、`_pipeline/rule-router.md`。
3. 目标作品轻量入口：`README.md`、`设定/当前状态.md`、`设定/分支记录.md` 或同类文件。
4. 目标作品 `设定/故事圣经.md`、`设定/风格指南.md`、`设定/伏笔表.md`。
5. 本单元出场角色的人物卡。
6. 如是续写，读取最近主干章节尾部和必要相邻章节。

如果缺少上述文件，应在规划中标注“上下文缺口”，不要凭空补稳定设定。

## 规划约束

- 不直接写正文，除非用户明确要求进入写作。
- 不把三章规划写进 `AGENTS.md`、`PROJECT.md` 或 `WORKFLOW.md`。
- 已确认的规划可写入目标作品 `设定/章节规划.md`、`设定/当前状态.md`、`_ledger/` 或用户指定路径。
- 没有章节接力卡的规划只能视为草案；进入正式生成前必须补齐。
- 如果规划中新增角色状态、秘密、伏笔或世界观事实，必须列入待同步项。

## 后续动作

- 用户确认后，按章节逐章写作或润色。
- 写作每章后执行章节首尾衔接、文风质量、规避词和设定一致性检查。
- 正文修改后按项目规则更新字数统计和必要账本。
