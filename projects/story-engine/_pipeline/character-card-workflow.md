# 人物卡同步工作流

## 目的

人物卡是正文连续性的核心事实层。每个主要角色应维护独立人物卡文件；正文写作、润色、改写、分支试写和发布整理中，只要出现对应人物，就必须读取该人物的人物卡，并在剧情新增或设定变化后同步更新人物卡。

## 文件标准

推荐结构：

```text
<作品>/设定/人物卡/
  <角色名>.md
```

现有合并版 `设定/角色卡.md` 暂作为旧版索引或迁移来源保留；拆分前，仍按该文件读取角色信息。拆分时不要直接删除旧文件，应先建立迁移记录，确认每个角色的新文件路径和来源段落。

## 读取规则

1. 任务开始时先判断目标章节、分支或发布稿涉及哪些角色。
2. 若角色已有独立人物卡，读取 `<作品>/设定/人物卡/<角色名>.md`。
3. 若尚未拆分独立人物卡，读取 `<作品>/设定/角色卡.md`，并标记该角色“待拆分独立人物卡”。
4. 若正文新增角色但没有人物卡，先创建或建议创建独立人物卡草案，并标记关键设定为“待确认”。
5. 涉及角色关系、心理变化、能力状态、创伤、秘密、约定、记忆、身体状态、社会关系或重要选择时，必须读取相关人物卡。

## 更新规则

正文或分支中出现以下情况时，应同步更新人物卡：

- 新剧情让角色获得新的经历、记忆、习惯、关系变化或心理变化。
- 角色状态发生变化，包括身份、立场、身体状态、伤病、能力、资源、限制或目标。
- 对白或行动确立了新的性格细节、禁忌、偏好、弱点、秘密或伏笔。
- 润色或重写改变了角色动机、关系强度、信息掌握程度或时间线位置。
- 分支稿形成可复用设定时，需要记录分支名、来源章节和是否进入主干。

更新人物卡时应保留来源：

```markdown
## 经历记录

- YYYY-MM-DD｜来源：<章节或分支路径>｜状态：主干/分支/待确认｜内容：……
```

## 回答与交付规则

当任务涉及正文创作、润色、改写、分支试写、发布整理或剧情规划时，最终回复应同时说明人物卡处理情况：

- 已读取的人物卡路径。
- 本次新增或改动的人物经历。
- 已写入的人物卡路径，或建议写入但等待用户确认的条目。
- 若尚未拆分独立人物卡，说明当前读取的是合并版 `设定/角色卡.md`，并建议拆分到 `设定/人物卡/<角色名>.md`。

## 默认约定

- 人物卡跟随正文走，正文事实变化后不能只改正文而不处理人物卡。
- `原文/` 默认只读；从原文抽取的人物经历应标注来源，不能直接覆盖旧事实。
- 分支经历不自动进入主干人物卡结论；需要标注分支来源和采纳状态。
- 不确定的新增信息必须标为“待确认”，不能伪装成既定事实。
