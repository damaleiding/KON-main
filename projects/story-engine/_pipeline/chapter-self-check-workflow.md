# 章节自检工作流

## 目的

用于在生成、润色、改写、拆章、合并或用户指定检查章节后，对正文进行项目内一致性自检，确保新文本不偏离作品设定、当前状态、角色卡、伏笔和风格要求。

自检是“建议阶段”，不是“修改阶段”。除非用户明确要求进入修改，否则自检后只输出问题、依据和修改建议，不直接改正文文件。

## 触发场景

- 用户明确要求“检查”“自检”“校对”“查设定”“查角色一致性”“查风格”。
- Agent 完成章节生成、续写、润色、改写、合并或发布整理后。
- 正文出现新增角色状态、关系变化、能力规则、时间线推进、伏笔回收或世界观解释时。
- 用户指定某个章节、某组章节、某个分支或某个发布稿进行质量检查时。

## 必读上下文

执行自检前，按目标作品读取最小必要上下文：

1. 目标正文文件。
2. `设定/故事圣经.md`。
3. `设定/风格指南.md`。
4. `设定/当前状态.md`。
5. `设定/伏笔表.md`。
6. `设定/分支记录.md` 或同类状态记录。
7. `设定/角色卡.md`。
8. 正文中出场角色对应的 `设定/人物卡/*.md`。
9. 如任务涉及发布，读取 `发布/` 和发布目标要求。
10. 如任务涉及分支，读取对应 `分支/` 与主干参照章节。

如果作品缺少上述文件，应先在自检结果中标记“上下文缺口”，不要凭空补设定。

## 检查维度

### 设定一致性

- 核心世界观、能力规则、身体状态、时间线和地点是否与 `故事圣经.md` 一致。
- 新增设定是否有来源；没有来源的新增事实是否标记为“待确认”。
- 章节事实是否与 `当前状态.md`、`分支记录.md` 或主干进度冲突。

### 角色一致性

- 出场角色的身份、性格、说话方式、关系网络、行动动机是否符合人物卡。
- 角色经历、心理、身体状态、关系、秘密或限制是否发生变化。
- 发生变化时，是否需要同步更新独立人物卡或在最终回复中列出“待同步人物卡条目”。

### 风格一致性

- 叙事节奏、对白风格、描写密度是否符合 `风格指南.md`。
- 是否出现作品明确避免的词汇、语气、比喻、叙事视角或表达习惯。
- 是否保持目标作品原有的人称、章节标题、段落节奏和结尾格式。

### 伏笔与结构

- 已埋伏笔是否被误删、误解或提前回收。
- 新增伏笔是否记录到 `伏笔表.md` 或在最终回复中列为待同步。
- 章节开头、转折、结尾是否承接前后文，不制造无来源跳跃。
- 是否继承上一章至少一个具体状态，并向下一章交付新的可执行状态。
- 信息账、资源账、关系账、风险账是否至少一项发生变化。
- 主要对话是否推动行动、判断或关系变化，而不是只解释设定或重复情绪。

### 格式与生产记录

- 每章/每部分结尾是否有且只有一行字数统计。
- 字数统计口径必须为“非空白 Unicode 字符数”。
- 文件命名、章节编号、目录层级是否符合当前作品格式。
- 生成或重要改写是否需要保存 prompt、输入参考、模型、时间、输出路径和筛选结论。

## 输出格式

自检结果优先输出为 HTML 网页报告，而不是只输出 Markdown。网页报告用于让用户持续查看、逐项确认和划掉已修复问题。

HTML 报告必须包含：

- 总览卡片：检查对象、检查日期、结论、问题数量、未修改正文声明。
- 任务清单：每个问题一个稳定 ID，例如 `QY2-ALL-001`。
- 问题模块：每个问题必须是独立模块或卡片，模块可持续保留、标记状态和追加复查记录。
- 交互展开：每个问题模块应支持双击展开/收起详情；详情区显示更细的证据、原文短引、判断依据和建议，不要把所有细节堆在总览层。
- 状态样式：未处理、待确认、已修复；已修复问题必须用删除线保留在页面上，不删除。
- 证据引用：可引用章节标题、非露骨正文片段、文件名、一级标题、目录项或设定条目来辅助理解；不得引用露骨肉戏细节；涉及原文核对时应给出文件名、行号、触发词和短引。
- 原文标注：详情区里的原文短引应使用注释、标红、背景色或高亮块标出怀疑位置，并明确说明“为什么怀疑这里有问题”。
- 修改建议：每个问题给出可执行建议，而不是直接改正文。
- 可视化辅助：可以使用抽象图、流程图、状态图或任务看板；如果使用网页图片，必须使用工作区规定的 `text_to_image` 图片 URL。

Markdown 可以作为补充账本，但默认交付和后续维护应以 HTML 报告为主。

结构参考：

```text
页面标题：作品｜版本｜章节/范围｜自检建议

总览：
- 结论：通过 / 有问题需修正 / 上下文不足
- 建议模式：只给修改意见，未改正文

任务清单：
- ID：
- 状态：未处理 / 待确认 / 已修复
- 严重度：高 / 中 / 低
- 位置：章节或文件路径
- 问题：具体冲突或风险
- 依据：引用的设定、人物卡、当前状态或风格要求
- 修改建议：建议增删改哪类内容、调整什么语气、补什么承接或伏笔
- 证据引用：只放非露骨、可安全展示的短引用或标题证据
- 详情交互：双击问题模块展开，显示原文短引、红色触发词、黄色背景怀疑句、旁注说明

- 人物卡：
- 当前状态：

- 分支记录：

- 建议 1：
- 建议 2：
- 可选方案：

格式检查：
- 字数统计：
- 文件命名：
- 章节连续性：
```

如果没有发现问题，必须明确说明“未发现设定/角色/风格冲突”，并列出仍存在的上下文缺口或未检查范围。

## 修正规则

- 自检默认只报告问题和修改建议，不直接改正文。
- 用户要求“帮我改掉”“修正后覆盖”“按第 N 条建议改”时，才进入修改阶段。
- 进入修改阶段前，先按 `text-version-backup-workflow.md` 备份会改动的文件。
- 修正正文后必须重新执行一次本工作流的关键检查项。
- 大段正文修改、章节合并、发布整理、重要审稿结论或用户明确要求记录时，创建或更新分章节账本，并同步更新 `_ledger/iteration-ledger.md` 总索引；轻量修正可只在最终回复或相关状态文件中说明。
- 如果本次自检已有 HTML 报告，后续用户确认“某个问题已改掉”后，应更新对应问题状态为“已修复”，并用删除线保留原问题文本。
- 分章节账本路径统一为 `_ledger/iterations/<作品名>/<版本或分支名>/`。
- 分章节账本文件名必须带有作品名、版本或分支名、章节编号或章节名、修改日期和操作类型，推荐格式：`YYYYMMDD_<作品名>_<版本或分支名>_<章节编号或章节名>_<操作类型>.md`。
- 如只更新人物卡、当前状态、伏笔表或分支记录，应说明来源章节和更新原因；是否写入章节账本按影响范围判断。
