# 路径结构与命名规则

本文是 `projects/story-engine` 的项目级路径、命名和生成落点规则。它用于约束新文件怎么放、怎么命名、由哪个区域生成，以及生成后要同步哪些索引或账本。

当前原则是：保留既有作品目录和人工路径习惯，不直接重命名旧正文；从本规则生效后，新增文件优先按这里的结构和命名落点。

## 总原则

- 文件系统是事实层；聊天记录、临时输出和未落盘 prompt 不作为事实来源。
- 目录结构先分用途，再分作品，再分版本或任务；不要把同一类文件散落到多个含义不明的位置。
- 既有中文作品名和正文目录保留；新增技术目录、索引、脚本、JSON、schema 和工具文件优先使用小写英文、数字和连字符。
- 人类阅读优先的小说正文、设定、审稿结论和说明文档可以使用中文文件名；机器读取或跨工具引用的文件优先使用稳定英文名。
- 新增文件名避免 ASCII 冒号、斜杠、反斜杠、引号、问号、星号、尖括号和竖线；章节标题中的冒号统一使用中文全角冒号 `：`。
- 正文、设定和发布稿物理迁移前必须先写迁移表，列出旧路径、新路径、引用风险、备份和回滚方式。
- `原文/` 默认只读；所有改写、拆分、清理、合并和发布整理都从工作稿、分支或主干生成。
- 每次生成正式正文、发布稿、重要 prompt 或审稿结论，都要能追溯输入、模型或工具、输出路径、用途、版本和筛选结论。

## Story Canvas 桥接分区

- Story Engine 只维护生成层：写作规则、prompt、范文学习、正文事实、审稿和账本。
- Story Canvas 维护工具层：网页 UI、sidecar、历史快照、server 和工具测试。
- 两者通过 `docs/rules/canvas-bridge-contract.md` 交接，例如生成请求、用户直接意见、剧情块锚点、候选状态和输出路径。
- Story Engine 不把网页工具实现写入本项目；Story Canvas 不维护生成规则全文。

## 标准路径骨架

### 项目级骨架

```text
projects/story-engine/
  AGENTS.md
  PROJECT.md
  WORKFLOW.md
  story-engine_project-brief.html
  docs/
    current-layout.md
    rules/
      README.md
      canvas-bridge-contract.md
      path-and-naming.md
  _pipeline/
    context-routes.md
    rule-router.md
  _ledger/
    iteration-ledger.md
    iterations/
  refs/
  prompts/
  outputs/
  review/
  trash/
  _tmp/
  _backups/
  tools/
  <作品名>/
```

项目级目录只放跨作品规则、流程、索引、公共 prompt、公共输出和公共记录。具体正文、设定和发布稿优先留在对应作品目录内。

### 作品级骨架

```text
projects/story-engine/<作品名>/
  README.md
  原文/
  设定/
    当前状态.md
    故事圣经.md
    风格指南.md
    伏笔表.md
    分支记录.md
    人物卡/
  主干/
    <版本名>/
  分支/
    <分支名>/
  发布/
    <发布目标>/
  prompts/
  _ledger/
```

`prompts/` 和 `_ledger/` 在作品内是可选但允许的局部生产记录；如果 prompt 或账本明显会跨作品复用，应同步或迁移到项目级 `prompts/`、`_ledger/` 或 `docs/`。

## 命名基本格式

| 类型 | 推荐格式 | 示例 |
| --- | --- | --- |
| 章节正文 | `NN_第N章：短标题.md` | `03_第三章：拆解与初次协商.md` |
| 拆分章节 | `NN_第N章：短标题（上）.md` | `02_第一章：完美的裂痕（中）.md` |
| 索引或目录 | `00_<范围>_索引.md` 或 `00_<范围>_目录与字数统计.md` | `00_第一版润色_章节目录与字数统计.md` |
| 作品状态 | 固定中文名 | `当前状态.md`、`分支记录.md` |
| 人物卡 | `<角色名>.md` | `曲影.md` |
| prompt | `YYYYMMDD_<作品名>_<对象>_<用途>.md` | `20260531_曲影番外二_后续生成统一提示词.md` |
| 审稿记录 | `YYYYMMDD_<作品名>_<版本>_<范围>_<检查类型>.md` | `20260601_曲影番外二_主干第一版润色_前七章_多子Agent复检.md` |
| HTML 审稿报告 | 同审稿记录，扩展名 `.html` | `20260601_曲影番外二_主干第一版润色_前七章_多子Agent复检.html` |
| 迭代账本 | `YYYYMMDD_<作品名>_<版本或分支>_<范围>_<操作类型>.md` | `20260605_曲影番外二_主干第一版润色_08第八章_重写.md` |
| 发布稿 | `<作品名>_<来源版本>_<发布目标>稿.md` | `曲影番外二_主干第一版润色_GoogleDocs同步稿.md` |
| 发布清单 | `<作品名>_<来源版本>_<发布目标>同步清单.md` | `曲影番外二_主干第一版润色_GoogleDocs同步清单.md` |
| 迁移表 | `YYYYMMDD_<范围>_路径迁移表.md` | `20260628_pixiv-novel_路径迁移表.md` |
| 工具脚本 | `kebab-case` 或 `verb-object` | `backup-text-version.py`、`build-content.ps1` |
| story sidecar | 与正文同名，追加 `.story.json` | `第六章.story.json` |

章节文件开头的 `NN_` 是排序编号，不一定等于作品内自然章号；自然章号写在标题中。新增章节编号必须两位补零；超过 99 章时改为三位补零，并在索引中说明切换。

## 各区域生成规则

### `docs/`

用途：项目说明、结构整理、规则沉淀、迁移记录和复盘。

生成规则：

- 新增项目级说明、结构规则、迁移方案和复盘时放入 `docs/`。
- 可长期复用的项目级规则放入 `docs/rules/`，并更新 `docs/rules/README.md`。
- 修改目录结构、路径命名或同步边界时，同步检查 `docs/current-layout.md`。
- 不放正文候选稿、长 prompt、单轮审稿意见堆积和临时脚本。

### `docs/rules/`

用途：项目级长期规则。

生成规则：

- 只保存跨作品可复用的规则，例如路径命名、文本整理、章节规划、文风检查和规避词维护。
- 新增规则文件后必须更新 `docs/rules/README.md` 和 `_pipeline/rule-router.md`。
- 规则文件只写可执行约束、落点和流程，不写单章正文和一次性审稿结论。

### `_pipeline/`

用途：上下文路由、工作流、工具索引和可执行流程说明。

生成规则：

- 新增工作流命名为 `<task>-workflow.md`，例如 `text-organization-workflow.md`。
- 新增或修改路径规则后，要更新 `context-routes.md` 和 `rule-router.md`。
- 工具入口登记到 `tool-index.json`；不要只把工具用法写在聊天里。
- `_pipeline/` 不保存正文全文、候选稿全文或外部参考全文。

### `_ledger/`

用途：生产事实、版本流转、prompt 索引、审稿决策和故事画布数据。

生成规则：

- 大段改写、章节合并、发布整理、重要审稿结论和用户明确要求记录的修改，写入 `_ledger/iterations/<作品名>/<版本或分支>/`。
- 总索引 `_ledger/iteration-ledger.md` 只登记路径、日期、作品、范围、操作类型和一句话结论。
- 故事画布 schema、节点索引、reroll 和角色变化表放入 `_ledger/story-canvas/`。
- `_ledger/` 记录事实和结论，不存放未筛选候选稿全文。

### `refs/`

用途：跨作品参考资料入口。

生成规则：

- 外部参考资料按来源、作者、平台或用途建立子目录；当前 `refs/范文参考/` 默认不进入上下文。
- Pixiv 或同类外部参考文件推荐格式为 `[作者]_<来源ID>_<作品标题>.txt`，来源 ID 缺失时用 `unknown-id`。
- 参考资料旁应有索引或说明，标注作品、角色、用途、状态和注意事项。
- 未筛选、废弃、风险不明的参考不得默认进入 prompt。

### `prompts/`

用途：可复用写作、润色、审稿、替换和发布整理 prompt。

生成规则：

- 项目级通用 prompt 放项目 `prompts/`；只服务某作品的 prompt 可放 `<作品名>/prompts/`。
- prompt 文件名使用 `YYYYMMDD_<作品名或通用>_<对象>_<用途>.md`。
- prompt 正文应写明目标、模型、输入参考、限制条件、输出格式、版本差异和预期用途。
- 修改既有 prompt 时记录源 prompt、问题症状、修改点、风险和审稿结论。

### `outputs/`

用途：生成、改写、整理和导出的阶段性结果。

生成规则：

- 临时但可能需要复查的结果放项目 `outputs/`，或放目标作品内指定输出目录。
- 推荐按日期或任务建立子目录：`outputs/YYYYMMDD_<作品名>_<任务>/`。
- 输出文件名使用 `YYYYMMDD_<作品名>_<来源版本>_<对象>_<用途>.md`。
- 被采纳内容进入 `主干/` 或 `发布/` 前，应记录来源和筛选结论；未采纳内容保留在 `outputs/` 或移入 `trash/`。

### `review/`

用途：审稿记录、候选稿对比、复检报告和采纳结论。

生成规则：

- 审稿文件命名为 `YYYYMMDD_<作品名>_<版本>_<范围>_<检查类型>.md` 或 `.html`。
- 审稿结论必须区分 `selected`、`rejected`、`needs_review`、`deprecated` 或项目约定状态。
- 审稿报告可以引用正文路径和短摘录，但不把整章候选稿塞进报告。
- 重要采纳结论同步登记到 `_ledger/iteration-ledger.md` 或分章节账本。

### `_tmp/`

用途：一次性脚本、临时 prompt、临时合并稿、排查中间文件和调试输出。

生成规则：

- 临时文件统一放 `_tmp/`，文件名前缀建议为日期或任务：`YYYYMMDD_<task>_<name>`.
- `_tmp/` 默认不纳入 Git，也不作为 prompt 默认输入。
- 临时成果一旦变成事实，应迁移到 `docs/`、`_ledger/`、`review/`、`prompts/`、`outputs/` 或正式工具目录。

### `trash/`

用途：废弃稿、失败尝试、过期中间产物和不再采用的材料。

生成规则：

- 被明确废弃但仍需短期保留的材料放 `trash/`。
- 文件名保留原范围和废弃日期，推荐 `YYYYMMDD_deprecated_<原文件名>`。
- `trash/` 不作为默认上下文，不进入生成 prompt，除非任务明确要求追溯废稿。

### `90_工具/` 和工作区 `tools/`

用途：旧项目工具和可复用工作区工具。

生成规则：

- 仍依赖项目相对路径的旧工具可暂留 `90_工具/`。
- 可跨项目复用的工具应登记到 `_pipeline/tool-index.json`，成熟后上移到工作区 `tools/`。
- 新工具必须有 README 或说明，写清用途、输入、输出、同步边界和最小示例。
- 工具产生的临时输出默认写 `_tmp/` 或 `outputs/`，不写项目根目录。

## 作品区域生成规则

### `<作品名>/README.md`

用途：作品轻量入口。

生成规则：

- 每个作品应维护 `README.md`；缺失时优先补齐，不先深读全部正文。
- 入口至少写明作品目标、主干入口、设定入口、分支状态、发布状态、当前风险和下一步。
- 作品目录结构变化时，同步更新本文件和项目 `docs/current-layout.md`。

### `<作品名>/原文/`

用途：导入底稿、原始资料和来源说明。

生成规则：

- 原文文件保持导入状态，默认只读，不直接覆盖。
- 新增原文时同时写 `来源说明.md` 或在已有说明中补来源、导入日期、格式处理、授权或注意事项。
- 如果需要拆章、清理编码或转 Markdown，输出到 `主干/`、`分支/` 或 `outputs/`，不覆盖原文。

### `<作品名>/设定/`

用途：作品事实、人物卡、世界观、时间线、伏笔、风格和当前状态。

生成规则：

- 稳定事实写入 `故事圣经.md`、`当前状态.md`、`伏笔表.md`、`风格指南.md`、`分支记录.md` 或 `人物卡/`。
- 新设定未经用户确认时标注 `待确认`，不要写成已锁定事实。
- 正文改动影响角色经历、关系、心理、状态、秘密或伏笔时，同步人物卡或在最终回复列出待同步项。
- 设定文件不保存候选正文全文和长 prompt。

### `<作品名>/主干/`

用途：当前认可的正式正文或主要润色稿。

生成规则：

- 主干下按版本建立子目录，例如 `拆章原文/`、`第一版润色/`、`润色稿/`。
- 正文章节使用 `NN_第N章：短标题.md`；拆分章节使用 `（上）`、`（中）`、`（下）` 或 `（其一）` 等后缀。
- 主干正文修改前先执行备份工作流，只备份本次会改动的文件。
- 正文修改后更新唯一字数统计，默认口径为非空白 Unicode 字符数。
- 主干中只保留已认可正文和必要索引；大纲、临时重写稿、候选片段优先放 `outputs/`、`分支/` 或 `_tmp/`。

### `<作品名>/分支/`

用途：实验稿、重设稿、替代路线、局部增补和平行版本。

生成规则：

- 分支目录命名为短方向名，例如 `成人化重设/`、`新作/`、`后日谈/`。
- 新分支建议包含 `README.md` 或在 `设定/分支记录.md` 登记：目标、来源、差异、状态、可合并范围和风险。
- 分支章节可沿用原章节名，也可用 `NN_` 排序；进入主干前必须说明来源和替代范围。
- 分支不得直接生成发布稿，除非先被标记为已确认合并或用户明确指定本分支为发布来源。

### `<作品名>/发布/`

用途：对外上传、Google Docs 同步、平台发布或归档整理版本。

生成规则：

- 发布目标单独建子目录，例如 `GoogleDocs/`、`上传/`、`Pixiv/`。
- 发布稿只从 `主干/` 或已确认合并的分支生成。
- 发布稿命名为 `<作品名>_<来源版本>_<发布目标>稿.md`；同步清单命名为 `<作品名>_<来源版本>_<发布目标>同步清单.md`。
- 发布文件必须保留来源说明、排版规则、目标平台和同步状态。
- Google Docs、上传或发布动作只在用户明确要求时执行；准备稿不等于自动上传。

### `<作品名>/prompts/`

用途：只服务该作品的可复用 prompt。

生成规则：

- 命名同项目级 prompt：`YYYYMMDD_<作品名>_<对象>_<用途>.md`。
- 如果 prompt 已验证可跨作品复用，应复制或抽象到项目级 `prompts/`，并注明来源作品。

### `<作品名>/_ledger/`

用途：作品局部账本。

生成规则：

- 已存在作品局部账本的作品可继续使用，但重要记录应在项目级 `_ledger/iteration-ledger.md` 留索引。
- 新增作品若没有强需求，优先使用项目级 `_ledger/iterations/<作品名>/`，避免账本分裂。

## 生成后同步清单

| 生成内容 | 必须同步 | 按需同步 |
| --- | --- | --- |

| 新主干版本 | 作品 README 或状态文件、`docs/current-layout.md` | `_ledger/iteration-ledger.md` |
| 正文修改 | 备份、字数统计、必要账本 | 人物卡、伏笔表、当前状态 |
| 分支创建 | `设定/分支记录.md` | 作品 README、项目账本 |
| 分支合并 | 账本、主干索引、分支记录 | 人物卡、伏笔表、发布稿 |
| 发布稿生成 | 发布清单、来源说明、账本 | Google Docs 工作流记录 |
| prompt 生成 | prompt 文件自身元信息 | prompt 索引或账本 |
| 审稿报告 | `review/` 文件 | `_ledger/iteration-ledger.md` |
| 路径迁移 | 迁移表、`docs/current-layout.md`、相关 README | 工具索引、发布清单、上下文路由 |

## 不立刻清理的既有问题

以下问题先记录，不在无迁移表和用户确认时直接删除、重命名或归档：

- `projects/story-engine/曲影番外二/` 下仍有少量一次性 Python 脚本和 `__pycache__/`；整理前先确认是否迁入 `tools/`、归档或删除。
- 旧项目目录保留为历史归档/回滚入口，不作为新任务默认写入位置。
- 部分旧作品缺少独立 `README.md`，当前通过 `设定/当前状态.md` 等文件承担轻量入口。
- 部分章节文件存在重复标题、旧序号或 story sidecar 混排现象；整理时先建迁移表和索引修正方案。
- 旧工具目录保留为历史归档/回滚入口；生成层工具已迁入 `projects/story-engine/tools/`。
- 迁移后的命名清理候选项、顺序和回滚方式见工作区级文档 `docs/migration/20260629_story-engine_naming-cleanup-plan.md`；执行前仍需按批次补迁移表。
