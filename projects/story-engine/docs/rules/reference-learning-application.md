# 范文学习应用规则

本文把 `refs/范文参考/` 中已经完成的学习成果转成 Story Engine 的生成规则入口。它不复述范文，不保存原文桥段，也不把具体题材词条写入项目入口文件。

## 落点边界

- 范文原文：只放 `refs/范文参考/<条目>/licensed-texts/`，并由该目录 `.gitignore` 排除。
- 单篇或单系列分析：放 `refs/范文参考/<条目>/analysis/`。
- 可复用生成规则：放 `docs/rules/`，例如本文、`longform-generation.md`、`chapter-planning.md`。
- 可复用 prompt 模板：放 `prompts/`。
- 单轮生产记录：放 `_ledger/` 或 `review/`。
- `AGENTS.md` 只保留入口、边界、读取顺序和落点，不承载具体生成词条、范文技法全文或作品级偏好。

## 读取顺序

需要使用范文学习成果时：

1. 先读 `refs/范文参考/all-reference-learning-index.md`，确认目标条目、完成状态和使用边界。
2. 再读目标条目的 `analysis/structure-study.md`。
3. 短中篇读 `analysis/segment-map.md`；长篇读章节/篇章地图和 `analysis/long-form-techniques.md`。
4. 最后回到本文件，把分析结论转成章节规划、续写 prompt 或自检问题。
5. 只有用户明确要求且确有必要时，才最小范围读取原文；不得把长原文塞进 prompt。

## 已沉淀的可迁移规则

### 1. 短中篇强情境结构

适用：单篇、片段、短中篇分支试写和单章重写。

- 开篇前 10% 必须建立明确压力、限制或角色目标。
- 中段至少发生一次主动权、关系状态、身份暴露、风险窗口或判断依据变化。
- 场景不能只堆氛围；每个主要场景要改变行动、信息、资源、关系或风险中的一项。
- 结尾必须固定一个新状态或余波，让后续章节可接。
- 敏感或成人向范文只迁移结构、节奏、视角、状态变化和上下文衔接，不迁移具体桥段和露骨表达。

### 2. 长篇章节接力

适用：正式续写、重写、三章规划和长篇分支。

- 先按 `longform-generation.md` 填写章节接力卡。
- 章首承接上一章的具体状态：物件、地点、伤害、承诺、误会、风险、资源变化或情绪后果。
- 本章必须产出至少一个可验证事实、可执行行动或不可逆关系变化。
- 章尾留下下一章能直接接住的动作、物件、约定、未完成任务、风险窗口或信息缺口。

### 3. 双线信息互证

适用：双视角、远距离协作、通信、调查、任务回传和多线叙事。

- 切线不是换视角，而是信息交接。
- 每次信息交接至少包含：发送者、接收者、验证动作、验证结果、回传后果。
- 信息不能只靠口头解释；优先用地点、物件、记录、行动和第三方反应验证。
- 如果一条线连续两次没有改变另一条线的行动或判断，应暂停、合并或改写。

### 4. 硬约束与资源账

适用：生存、技术、任务、身体恢复、发布同步、调查和任何有明确限制的章节。

- 把压力拆成可追踪变量：时间、体力、金钱、道具、空间、损坏状态、机会、社会风险或规则限制。
- 成功也要付出代价；失败必须产生新知识、排除路径、暴露边界或改变关系。
- 章节结尾至少更新资源账、风险账或方案账中的一项。
- 技术细节服务选择和后果，不做资料展示。

### 5. 物件和场景钩子

适用：章节规划、悬疑推进、系列续作、分支重写和 Story Canvas 节点整理。

- 每个三章单元至少有一个可操作物件、地点或制度性限制。
- 关键物件不能只象征主题，必须改变行动、风险判断或后续选择。
- 场景第一次出现负责建立日常功能，第二次出现应发生意义变化，终局或阶段结尾要处理后果。
- Story Canvas 节点可记录 `物件状态`、`现实任务`、`下一章必须处理`，供生成层读取。

### 6. 读者预期与题材边界

适用：题材选择、分支试写、风格调整和高风险内容边界。

- 写作前明确本章承诺给读者的体验：悬疑、关系推进、任务完成、情绪释放、风格实验或世界观扩展。
- 不让题材刺激替代剧情推进；题材元素必须服务状态变化、关系变化或风险变化。
- 不把单一范文风格硬套给所有作品；每次引用范文技法都要说明迁移的是结构机制，不是题材外壳。
- 涉及敏感文本时，只使用机制层摘要，并在 prompt 中写明“只参考结构，不参考具体桥段或表达”。

## 生成前检查卡

正式使用范文学习成果前，先补这张卡：

```text
参考来源：
读取的 analysis 文件：
本次只迁移的机制：
本次禁止迁移的内容：
目标作品/章节：
要强化的章节功能：
要更新的账本：
生成后自检问题：
```

## 生成后自检

1. 这次使用的是范文机制，还是不小心套用了题材外壳？
2. 是否把原文桥段、长摘录或露骨细节带进 prompt？
3. 本章是否继承上一章具体状态？
4. 本章是否改变行动、信息、资源、关系或风险？
5. 章尾是否留下下一章能执行的交付物？
6. 是否需要把新经验补回 `refs/范文参考/`、`docs/rules/`、`prompts/` 或 `_ledger/`？
